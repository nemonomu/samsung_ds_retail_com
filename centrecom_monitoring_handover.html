Centrecom Monitoring Screenshot Handover

작성일: 2026-06-07 / 대상 저장소: C:\samsung_ds_retail_com

이 문서는 centrecom.py에 monitoring screenshot 후처리를 내장하고, 기존 NULL 증거 스크린샷을 재사용하도록 변경한 내용을 인수인계하기 위한 문서입니다.

1. 목적

Centrecom 크롤링 중 이미 NULL 증거 스크린샷이 S3에 저장된 경우, monitoring_capture.py가 같은 페이지를 다시 열어 중복 캡처하지 않도록 했습니다. 대신 기존 S3 이미지를 ds_monitoring_file에 등록하고 ds_monitoring_report_anomaly.screenshot_id에 연결합니다.

2. 변경 파일

파일 변경 요약
centrecom.py Centrecom 전용 NULL 판정 필드 확장, 크롤링 완료 후 monitoring 캡처 자동 호출, monitoring 조회 날짜를 Centrecom 현지 crawl_datetime 기준으로 설정.
monitoring/monitoring_capture.py 기존 NULL 스크린샷 S3 key를 먼저 조회하여 DB file record와 anomaly screenshot_id를 연결. 기존 이미지가 없을 때만 새 브라우저를 띄워 캡처.

3. 전체 흐름

1. centrecom.py가 DB에서 Centrecom 대상 URL을 로드합니다.
2. 각 URL을 크롤링하고 결과를 centrecom_price_crawl_tbl_au에 저장합니다.
3. 결과에 NULL 증거 필드가 있으면 null_screenshot.capture_and_upload()가 S3에 증거 이미지를 저장합니다.
4. auto_recovery_run(target_key='au')가 파일 업로드와 알림/모니터링 후처리를 수행합니다.
5. Centrecom 드라이버를 종료한 뒤 run_monitoring_capture_for_centrecom()가 실행됩니다.
6. monitoring anomaly 중 screenshot_id IS NULL인 URL을 조회합니다.
7. 같은 날짜/리테일러/SKU의 기존 NULL 스크린샷이 있으면 재사용합니다.
8. 기존 NULL 스크린샷이 없으면 같은 날짜/리테일러/SKU의 기존 monitoring 캡처를 삭제한 뒤 새로 캡처합니다.

4. Centrecom NULL 증거 스크린샷

Centrecom에서는 아래 필드 중 하나라도 비어 있으면 증거 스크린샷 대상입니다. 

title
retailprice
ships_from
sold_by
imageurl

구현 위치는 centrecom.py의 CENTRECOM_NULL_SCREENSHOT_FIELDS와 should_capture_centrecom_null_screenshot()입니다. 전역 null_screenshot.is_null_result()는 다른 리테일러 영향 방지를 위해 수정하지 않았습니다.

5. S3 경로

구분 S3 key 형식 역할
NULL 증거 스크린샷 ds-null-screenshots/YYYY/YYYYMM/YYYYMMDD/centrecom/centrecom_{sku}_{timestamp}.png Centrecom 크롤링 중 NULL 발생 당시 페이지 증거
Monitoring 신규 캡처 YYYY/YYYYMM/YYYYMMDD/centrecom/centrecom_{sku}_{timestamp}.png 기존 NULL 증거가 없을 때 anomaly용으로 새 캡처

6. DB 로드 및 저장

단계 설정/테이블 설명
Centrecom 설정/대상 로드 DB_CONFIG_V2, mall_selectors, samsung_price_tracking_list 셀렉터와 크롤링 대상 URL을 로드합니다.
Centrecom 결과 저장 centrecom_price_crawl_tbl_au, centrecom_crawl_logs 크롤링 결과와 로그를 저장합니다.
Monitoring 대상 조회 DB_CONFIG, ds_monitoring_report_anomaly, ds_monitoring_targets LOWER(t.retailer) = 'centrecom', a.crawl_date = crawl_date, a.screenshot_id IS NULL, a.is_del = 0 조건으로 조회합니다.
기존 NULL 스크린샷 연결 ds_monitoring_file, ds_monitoring_report_anomaly.screenshot_id 기존 S3 object의 file_name, file_path, Size를 사용해 file record를 만들고 anomaly에 연결합니다.

7. 핵심 함수 관계

함수 파일 역할
should_capture_centrecom_null_screenshot(result) centrecom.py Centrecom 결과에서 NULL 증거 스크린샷이 필요한지 판정합니다.
capture_and_upload(driver, 'centrecom', sku, url) null_screenshot.py 현재 브라우저 화면을 캡처하고 NULL 전용 S3 경로에 업로드합니다.
run_monitoring_capture_for_centrecom(crawl_date) centrecom.py Centrecom 완료 후 monitoring anomaly 캡처/연결을 자동 실행합니다.
get_anomaly_urls('centrecom', crawl_date) monitoring/monitoring_capture.py 아직 screenshot_id가 없는 monitoring anomaly URL을 조회합니다.
link_existing_null_screenshot(identifier, anomaly_id) monitoring/monitoring_capture.py 기존 NULL S3 object를 찾아 DB file record와 anomaly screenshot_id를 연결합니다.
process_url(url, identifier, anomaly_id) monitoring/monitoring_capture.py 먼저 기존 NULL 스크린샷 재사용을 시도하고, 실패 시 기존 monitoring 캡처를 정리한 뒤 새 캡처를 수행합니다.
delete_existing_monitoring_screenshots(file_path, identifier) monitoring/monitoring_capture.py 모든 리테일러에 공통 적용되는 정리 함수입니다. 같은 날짜/리테일러/SKU prefix의 기존 monitoring S3 object를 삭제합니다.

8. 예외 및 fallback

  • 기존 NULL 스크린샷이 없으면 기존 monitoring 방식대로 새 브라우저를 띄워 캡처합니다.
  • 새 monitoring 캡처 업로드 전 같은 날짜/리테일러/SKU의 기존 monitoring S3 object를 삭제합니다.
  • S3 list 또는 DB 연결/저장 실패 시 재사용은 실패 처리되고 새 캡처 경로로 넘어갑니다.
  • Centrecom monitoring 자동 실행 실패는 로그만 남기고 Centrecom 전체 프로세스를 강제 실패시키지 않습니다.
  • 전부 기존 NULL 스크린샷으로 연결 가능한 경우 monitoring용 새 Chrome은 뜨지 않습니다.

9. 검증 체크리스트

항목 결과
공백/패치 오류 통과 - git diff --check -- centrecom.py monitoring\monitoring_capture.py

날짜 기준 monitoring 조회 날짜는 KST 오늘이 아니라 Centrecom 결과의 crawl_datetime 현지 날짜를 우선 사용합니다.

11. 운영상 주의점

  • 중요: ds_monitoring_report_anomaly row가 auto_recovery_run() 이후 즉시 생성되어 있어야 자동 연결이 됩니다. 외부 배치가 늦게 anomaly를 만드는 구조라면 첫 실행에서는 조회 대상이 0건일 수 있습니다.
  • ds_monitoring_targets.retailer 값은 centrecom이어야 합니다. au_centrecom만 있으면 조회되지 않습니다.
  • 동일 날짜/SKU에 NULL 스크린샷이 여러 개 있으면 S3 LastModified가 가장 최신인 object를 연결합니다.
  • 기존 NULL 스크린샷을 연결할 때 새 S3 업로드는 하지 않지만, 모니터링 리포트 연결을 위해 ds_monitoring_file record는 새로 생성합니다.
  • 기존 monitoring S3 object 삭제는 모든 리테일러에 공통 적용됩니다. 단, identifier가 없는 경우에는 너무 넓은 prefix 삭제를 막기 위해 삭제를 건너뜁니다.
